# Testing the Backend API

This document provides instructions on how to test the core endpoints of the PubMed RAG backend service using the automatically generated FastAPI documentation (Swagger UI).

## Prerequisites

1.  **Backend Server Running:** Ensure the backend server is running. Follow the setup and execution steps in `README.md` (activate virtual environment, run `uvicorn main:app --reload --port 8000 --host 0.0.0.0` from the `backend` directory).
2.  **API Keys Configured:** Make sure your `GOOGLE_API_KEY` (and optionally `PUBMED_API_KEY`) are correctly set in the `backend/.env` file.

## Accessing the API Documentation

FastAPI provides interactive documentation via Swagger UI.

*   Open your web browser and navigate to: **`http://127.0.0.1:8000/docs`** (or `http://localhost:8000/docs`).

You will see a list of available API endpoints.

## Testing the `/search` Endpoint (POST)

*   **Purpose:** This endpoint takes a user query, searches the live PubMed database for relevant article abstracts using the E-utilities API, fetches the details (abstracts, metadata), and then *adds these articles to the local ChromaDB vector store* by generating embeddings for the abstracts. This populates the database for the `/answer` endpoint.

*   **Steps:**
    1.  In the Swagger UI (`/docs`), find the `POST /search` endpoint and click to expand it.
    2.  Click the **"Try it out"** button.
    3.  In the **"Request body"** section (a JSON editor), enter a search query and optionally specify `max_results`. Example:
        ```json
        {
          "query": "effectiveness of mRNA vaccines for COVID-19",
          "max_results": 5
        }
        ```
    4.  Click the blue **"Execute"** button.

*   **Expected Results:**
    *   **Response Code:** You should see a `200` status code indicating success.
    *   **Response Body:** The response will be a JSON object containing:
        *   `articles`: A list of dictionaries, where each dictionary represents a fetched article with its `pmid`, `title`, `abstract`, `authors`, and `year`.
        *   `count`: The number of articles returned in the list.
    *   **Server Logs (Uvicorn Terminal):** Check the terminal where Uvicorn is running. You should observe log messages indicating:
        *   Receiving the POST request to `/search`.
        *   Searching PubMed (`Searching PubMed with query...`, `Found X PubMed IDs...`).
        *   Fetching abstracts (`Fetching abstracts for Y PMIDs...`, `Successfully fetched and parsed details...`).
        *   Generating embeddings (`Generating embeddings for Z documents...`, `Embeddings generated.`).
        *   Adding documents to ChromaDB (`Successfully added/updated Z documents...`).

## Testing the `/answer` Endpoint (POST)

*   **Purpose:** This endpoint implements the core Retrieval-Augmented Generation (RAG) functionality. It takes a user query, generates an embedding for it, searches the *local ChromaDB vector store* (populated by previous `/search` calls) for the most relevant abstracts based on semantic similarity, sends these retrieved abstracts (as context) along with the original query to the Google Gemini LLM, receives the generated answer, formats citations for the used abstracts, and returns the complete response.

*   **Steps:**
    1.  **Prerequisite:** Ensure you have run `/search` at least once with a query related to the topic you want to ask about, so that relevant abstracts exist in the local ChromaDB.
    2.  In the Swagger UI (`/docs`), find the `POST /answer` endpoint and click to expand it.
    3.  Click the **"Try it out"** button.
    4.  In the **"Request body"** section, enter a question related to the topic you searched for previously. Example:
        ```json
        {
          "query": "How effective are mRNA vaccines against COVID-19 based on recent studies?",
          "max_results": null
        }
        ```
        *(Note: `max_results` in the request body for `/answer` is not currently used by the endpoint logic but is part of the `SearchQuery` model.)*
    5.  Click the blue **"Execute"** button.

*   **Expected Results:**
    *   **Response Code:** You should see a `200` status code.
    *   **Response Body:** The response will be a JSON object containing:
        *   `answer`: A string containing the answer generated by the Google Gemini model, based *only* on the context provided by the retrieved abstracts.
        *   `citations`: A list of strings, where each string is a formatted citation for one of the articles used as context.
        *   `retrieved_articles`: A list of dictionaries representing the articles retrieved from ChromaDB and used as context for the LLM.
    *   **Server Logs (Uvicorn Terminal):** Check the Uvicorn terminal logs. You should observe messages indicating:
        *   Receiving the POST request to `/answer`.
        *   Querying the ChromaDB collection (`Retrieved W results for query...`).
        *   Sending the request to the Google Gemini API (`Sending request to Google Gemini model...`).
        *   Receiving the response from Gemini (`Received response from Google Gemini.`).

## Important Notes

*   The `/answer` endpoint relies on the content stored in the local ChromaDB. You must run `/search` first to populate this database with relevant articles before `/answer` can provide meaningful results for a given topic.
*   Always monitor the Uvicorn server logs in your terminal. They provide the most detailed information about the backend's operations and are crucial for diagnosing any errors (e.g., invalid API keys, network problems, data parsing issues).
